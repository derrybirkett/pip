# Planning Pattern

**Pattern Type**: Agent Workflow  
**Primary Users**: CEO, CPO, CTO, COO  
**Purpose**: Break ambiguous work into a sequenced plan with dependencies, owners, and validation.

## Overview

Use the Planning pattern when the work is too large, risky, or cross-functional to execute in a
single pass. The output is a concrete plan that makes scope, sequencing, and checkpoints explicit.

## Core Steps

1. Define the outcome and success criteria.
2. Capture constraints, risks, and assumptions.
3. Split the work into small, verifiable tasks.
4. Order tasks by dependency and risk.
5. Assign owners or responsible agents.
6. Define validation for each milestone.

## When to Use

- Roadmap planning and initiative shaping
- Large technical changes
- Cross-functional launches
- Security or operations audits

## Outputs

- A numbered implementation plan
- Known risks and open questions
- Clear handoff points between agents
- Validation steps before release
