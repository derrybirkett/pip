# Testing pip + hatch Integration: Agentic Operational Layer

## Overview

This document demonstrates how **pip** (pure governance) and **hatch** (executable tooling) work together to create an agentic operational layer that takes an idea from mission statement to deployed product surface.

**pip provides**: Agent governance, decision frameworks, delivery methodology, agentic patterns  
**hatch provides**: Code generation, project scaffolding, technical infrastructure

---

## Test Scenario: Build a Team Task Manager

### Phase 1: Mission & Discovery (pip-governed)

**Stakeholders**: CEO, CPO, CTO (pip agent roles)

**1.1 Define Mission** (`mission/mission.md` template)

```markdown
## Who It Serves
- Primary: Small remote teams (5-15 people)
- Secondary: Team leads, project managers

## Problem We Solve
- Teams struggle to track who's working on what
- Context switching between Slack, email, and task tools
- No lightweight "daily standup" view

## Solution Overview
- Real-time task board with team presence
- Quick task creation from anywhere
- Daily digest and @mentions
- Mobile-first design

## Vision & Outcomes
- Vision: Every remote team has instant task visibility
- Outcomes:
  1. Teams reduce status update meetings by 50%
  2. 80% task visibility within first week
  3. 10+ active teams within 90 days

## Success Metrics
- Daily active users per team: >60%
- Tasks created per user per week: >5
- Team retention at 30 days: >70%
```

**1.2 Apply Delivery Method** (`method/delivery-method.md`)

**CPO Decision**: Define data models

```yaml
Entities:
  - User (name, email, avatar, status)
  - Team (name, invite_code)
  - Task (title, description, assignee_id, status, due_date)
  - Comment (task_id, user_id, text, created_at)

Relationships:
  - User belongs to Team (many-to-many via team_members)
  - Task belongs to Team
  - Task assigned to User
  - Comment belongs to Task and User
```

**CPO Decision**: Define UI flows

```
Flow 1: New user onboarding
  → Sign up page
  → Join/Create team
  → See team board (empty state)
  → Create first task

Flow 2: Daily task management
  → Login → Team board (grouped by status)
  → Quick-add task
  → Drag to update status
  → @mention teammate in comment
  → Receive real-time notification
```

**3.2 CTO: Apply Agentic Patterns** (`patterns/agent-workflows/`)

**Use ReAct Pattern for Feature Implementation**:

```
Thought: Need to implement real-time task updates
Action: Research WebSocket vs SSE options in NestJS
Observation: NestJS has @nestjs/websockets, works with Socket.io
Thought: Socket.io provides room support for team isolation
Action: Implement WebSocket gateway in apps/api
Observation: Connection established, events firing
Thought: Need client-side subscription in dashboard
Action: Add socket.io-client to apps/dashboard
Observation: Real-time updates working across clients
Result: Real-time task sync implemented ✅
```

**Use Tool Use Pattern for Database Schema**:

```bash
# Agent uses Prisma schema as tool
# Located in: apps/api/prisma/schema.prisma

model Task {
  id          String   @id @default(cuid())
  title       String
  description String?
  status      String   @default("todo")
  assigneeId  String?
  teamId      String
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  
  assignee User?      @relation(fields: [assigneeId], references: [id])
  team     Team       @relation(fields: [teamId], references: [id])
  comments Comment[]
  
  @@index([teamId])
  @@index([assigneeId])
}

# Run migration
nx run api:prisma:migrate -- dev --name add_tasks
```

## Test Validation Criteria

### ✅ Pip Governance Working If:

1. **Decision Rights Clear**: Each decision has owner (CEO/CPO/CTO/etc)
2. **Patterns Applied**: Can trace use of ReAct, Tool Use, Multi-Agent Collaboration
3. **Methodology Followed**: Mission → Data Models → APIs → UI sequence evident
4. **Documentation Current**: activity-log.md and changelog.md maintained
5. **Agent Coordination**: Multiple agents collaborate without conflicts

### ✅ Hatch Tooling Working If:

1. **Generation Successful**: `hatch init` completes without errors
2. **Apps Start**: All dev servers run (`pnpm dev`)
3. **Tests Pass**: E2E and unit tests execute successfully
4. **Build Works**: Production build completes (`pnpm build`)
5. **Standards Met**: Linting, type-checking, accessibility checks pass

### ✅ Integration Working If:

1. **Seamless Handoff**: pip mission → hatch scaffold → pip-governed development
2. **No Duplication**: hatch provides execution, pip provides governance (clean separation)
3. **Agent Efficiency**: Agents use pip patterns to coordinate work on hatch foundation
4. **Traceability**: Can map feature back to mission → flow → implementation → test
5. **Velocity**: Time from idea to deployed feature is < 1 week

## Conclusion

**pip** provides the **governance layer** (who decides what, how to coordinate, which patterns to use)  
**hatch** provides the **execution layer** (generate code, scaffold infrastructure, setup tooling)

Together they enable **agentic operational efficiency**: AI agents can follow pip's governance to make coordinated decisions while using hatch to rapidly execute the technical foundation, dramatically reducing time from idea to production.

**Success Indicator**: An agent (or human acting as agent) can go from problem statement to deployed, tested, documented product surface in <5 days using this integrated approach.
